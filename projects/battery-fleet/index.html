Predicting which battery in a fleet of 140 dies first

An open-source anomaly detection and time-to-failure system built on the Severson fast-charging dataset, where the hard part is not predicting failure but that roughly 70% of the fleet never fails inside the window you get to observe.

Most of the fleet never fails

Of the 139 cells in the modeling set, 43 cross the 80% capacity threshold inside their recorded history. The other 96 stop while still above it, and every modeling decision on this project follows from that split.

The obvious approach is to regress cycles-to-failure on features from the early cycles. That needs a failure cycle for every cell, and 96 of 139 do not have one. Both of the usual ways around this are wrong, and wrong in a direction you can predict in advance.

Drop the cells without a label, and what is left is 43 cells that are, by construction, the ones that failed fastest. Half of them were below the threshold by cycle 492. Half of the cells just discarded were still above it past cycle 885. The model would learn from the short-lived tail of the fleet and then be asked to score the rest of it.

Use the last observed cycle as the failure cycle instead, and a cell that ran 2,237 cycles and finished at 91% capacity gets labeled as having failed at 2,237. Every censored cell gets a label that is too small, so the model inherits a systematic bias toward predicting failure early.

What the data actually supports

The fix is to stop predicting a time and predict a per-cycle risk instead. In person-period format each cell contributes one row per cycle interval it was observed for, carrying a binary outcome for whether it failed during that interval. A censored cell contributes every cycle it survived and then stops, which is exactly what is known about it. Nothing is dropped and no failure date is invented.

Two pieces sit on top of that. A next-step residual model gives day-to-day anomaly flags by comparing each cycle against what the cell's own recent history predicts. Conformal prediction wraps both, so a flag arrives with a calibrated interval rather than a bare number.

What was built

The data foundation is finished and the modeling layer is not, so what follows is a description of the ground the models will stand on.

Data

140 BEEP ProcessedCyclerRun files from the Severson fast-charging dataset, about 26 GB. Only the per-cycle summary block is parsed; the interpolated voltage, current and temperature traces are left on disk, which holds a full pass to roughly a second a file.

Pipeline

114,314 cell-cycle rows across 140 cells, written to two Parquet tables, one row per cell-cycle and one per cell, with DuckDB views over both for querying.

Cell identity

Barcode plus channel id is not a unique key here. Five pairs appear in two different files as genuinely different runs, with different cycle counts and different capacity trajectories. Those cells are disambiguated with the batch number from the filename rather than merged into one trajectory or dropped.

Validation

Uniqueness, coverage between the two tables, and physically impossible values. 44 internal-resistance readings sit at zero, eleven of them at cycles 12 and 13 and the rest late in life, from cycle 311 to 917. They are flagged and kept, as are 1,215 null charge durations and the one cell with a single recorded cycle, which is marked unfit for modeling rather than deleted.

Modeling

A discrete-time hazard model in person-period format for time to failure, a next-step residual model for anomaly flagging, and conformal prediction over both. None of this is in the repository yet.

Where it stands

Last updated September 2026.

Done

  • Ingestion across all 140 raw files, including the five cell-identity collisions
  • Two Parquet tables, 114,314 cell-cycle rows and 140 cell summaries, with DuckDB views over both
  • A validation suite that passes: no duplicate cell-cycle pairs, full coverage between the tables, and a count for every flagged value rather than a silent drop
  • Data documentation covering the schema, the cycle-10 reference choice, and each known gap

In progress

  • The modeling layer. The data foundation is complete and nothing past it is committed yet.
